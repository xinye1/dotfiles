    Prerequisites

    This setup is a diff against EndeavourOS Sway Community Edition, not against bare upstream sway. Starting anywhere else means the "what stock does" reasoning in the playbook won't line up.

    You should be able to log in and get a bar, a terminal on $mod+Return, and a launcher on $mod+d before changing anything.

    shell
    ❯ pgrep -x sway && echo "sway running"
❯ pgrep -xc swayidle          # stock leaks these — see phase 05
❯ ls /usr/share/themes
    01

    Packages

    Five additions over the CE base, plus one GTK theme that is not a package at all. The Nerd Font is the one people skip — everything appears to work without it because fontconfig silently falls back.

    shell
    ❯ sudo pacman -S --needed ttf-jetbrains-mono-nerd kanshi papirus-icon-theme

    ttf-jetbrains-mono-nerd — the patched font. kanshi — display hotplug profiles. papirus-icon-theme — icons for mako, fuzzel and GTK.

    shell
    ❯ yay -S nordic-theme papirus-folders

    Nothing in the base install provides a Nord GTK theme. papirus-folders supplies the recolouring script used in phase 05.

    shell
    ❯ git clone https://github.com/vinceliuice/Colloid-gtk-theme /tmp/colloid
❯ cd /tmp/colloid
❯ ./install.sh -d ~/.themes -c dark -s standard -t yellow --tweaks gruvbox

    Not from the AUR. gruvbox-gtk-theme-git depends on gtk-engine-murrine, which drags in a from-source gtk2 build for the sake of one theme. This installs into ~/.themes with no root and no engine, producing Colloid-Yellow-Dark-Gruvbox.

    Never pass -l / --libadwaita to that installer. It replaces ~/.config/gtk-4.0/gtk.css with its own — which is exactly the nwg-look failure mode in phase 07, and destroys the overrides this repo owns.

    Check

    fc-match "JetBrainsMono Nerd Font"not NotoSansMono
    ls -d /usr/share/themes/Nordicexists
    ls -d ~/.themes/Colloid-Yellow-Dark-Gruvboxexists

    Clone the repo

    Location matters. .stowrc pins --target=~ precisely because the repo does not live in $HOME — stow would otherwise link into the repo's parent.

    shell
    ❯ mkdir -p ~/repos && cd ~/repos
❯ git clone https://github.com/xinye1/dotfiles.git
❯ cd dotfiles
    shell
    ❯ sudo pacman -S --needed stow
    03

    Clear the conflicts

    Stow will not replace a real file with a symlink. A fresh install already has all of these, so they must move aside first — this is the step that fails if you skip it.

    shell
    # ~/.bashrc comes from /etc/skel on every Arch install
❯ mv ~/.bashrc ~/.bashrc.bak

# Folded packages need the whole directory gone, not just its files
❯ for d in sway waybar mako fuzzel nwg-drawer gtklock foot; do
❯     mv ~/.config/$d ~/.config/$d.bak 2>/dev/null
❯ done

# gtk is tracked file-by-file, so move only the tracked files
❯ mv ~/.gtkrc-2.0 ~/.gtkrc-2.0.bak 2>/dev/null
❯ rm -f ~/.config/gtk-3.0/settings.ini ~/.config/gtk-4.0/settings.ini
❯ rm -f ~/.config/gtk-4.0/gtk.css ~/.config/gtk-4.0/gtk-dark.css

    The two gtk-4.0 symlinks point into /usr/share/themes/Arc-Dark. They must go, or stow can't place the libadwaita overrides.

    Two large images live inside stock config dirs — a 3.3 MB wallpaper in ~/.config/sway and a 22 MB lock screen background in ~/.config/gtklock. Neither belongs in a dotfiles repo. Move them to ~/Pictures/wallpapers if you want to keep them; this setup uses a solid Nord background instead.

    04

    Stow the packages

    Always dry-run first. Stow exits 0 even when it links to the wrong place, so the exit code proves nothing — the dry run's output is the real check.

    shell
    ❯ cd ~/repos/dotfiles
❯ stow -n -v bash vim bin starship alacritty foot htop waybar \
        sway kanshi gtk mako fuzzel nwg-drawer gtklock

    Every LINK: line must point at ../repos/dotfiles/…. Any CONFLICT means phase 03 was incomplete.

    shell
    ❯ stow bash vim bin starship alacritty foot htop waybar \
        sway kanshi gtk mako fuzzel nwg-drawer gtklock

    Check — every path must resolve inside the repo

    readlink -f ~/.config/sway~/repos/dotfiles/…
    readlink -f ~/.config/waybar~/repos/dotfiles/…
    readlink -f ~/.gtkrc-2.0~/repos/dotfiles/…
    readlink -f ~/.local/bin/theme~/repos/dotfiles/…
    shell
    ❯ for p in sway waybar foot mako fuzzel gtklock nwg-drawer htop; do
❯     printf '%-12s ' "$p"
❯     if [ -L ~/.config/$p ]; then echo "folded (symlink)"; else echo "UNFOLDED (real dir)"; fi
❯ done

    Eight lines, every one folded (symlink). This is the property the whole theming model rests on — each package's palette fragments live inside it, so no second package ever has to write into these directories.

    Use the [ -L ] test, not ls -la ~/.config | grep -E ' foo$'. ls prints a symlink as foo -> target, so the $ anchor matches only the unfolded case: the command prints nothing and looks like a pass precisely when folding is healthy, and speaks up only when it is broken.

    Three packages are deliberately not folded. nwg-look writes into the gtk dirs; alacritty's optional themes/ clone lives inside its own; and ~/.local/bin (the bin package) holds untracked binaries that folding would drag into the repo. For those three, a newly added file is silently absent until you run stow -R <pkg>.

    05

    Steps that can't be stowed

    Untracked clones and things that write outside $HOME.

    shell
    ❯ sudo papirus-folders -C nordic -t Papirus-Dark

    Yes, nordic — not nord. papirus-folders rejects nord outright. Despite the name the icons are genuine Nord: folder-nordic.svg is drawn in #5E81AC, #81A1C1 and #ECEFF4. The GTK theme is likewise named Nordic. Run papirus-folders -l to see the list.

    Gruvbox has no entry on that list at all. The switcher uses yellow as the stand-in, gruvbox's signature accent. This is the one place in the setup where the palette is approximated rather than matched — and the only reason theme ever needs sudo, since papirus-folders writes into /usr/share/icons.

    shell
    # status bar, plus one colorscheme per palette
❯ git clone https://github.com/itchyny/lightline.vim \
        ~/.vim/pack/plugins/start/lightline
❯ git clone https://github.com/arcticicestudio/nord-vim \
        ~/.vim/pack/plugins/start/nord-vim
❯ git clone https://github.com/morhetz/gruvbox \
        ~/.vim/pack/plugins/start/gruvbox

    .vimrc guards the colorscheme source with filereadable, so vim still starts on a machine without these — it just opens uncoloured rather than erroring on every launch.

    shell
    ❯ git clone https://github.com/alacritty/alacritty-theme \
        ~/.config/alacritty/themes

    No longer required. alacritty.toml used to import nord.toml from this clone; it now imports its own switchable colors.toml fragment, so the repo describes the colours on its own. Clone it only to have other schemes to hand — and note it ships nord, nordic, nordfox and nord_light, three of which are not Nord.

    XDG_CURRENT_DESKTOP is empty in a stock session, and xdg-desktop-portal picks its backend from it. The sway config repairs this for systemd and dbus — which is what portals actually read — but only greetd can put it in sway's own environment. In /etc/greetd/config.toml:

    /etc/greetd/config.toml
    command = "env XDG_CURRENT_DESKTOP=sway sway"

    07

    Traps worth knowing

    Each of these produced a real bug in this setup. Full detail in PLAYBOOK.md §9.

    TrapWhat happensGuard
    nwg-look Rewrites every tracked GTK file on Apply; may replace stow symlinks outright git status after using it, then stow -R gtk
    exec_always Spawns another daemon on every reload — this is what leaked 40 swayidle processes Prefix with pkill -x <name>;
    exec Runs only at startup, so a reload can't repair it — the fix looks broken Use exec_always for anything idempotent
    exec export Silently does nothing; the subshell exits with the variable systemctl --user set-environment
    Font names fc-match returns something for any string, so a wrong name looks fine Family name has a space; Nerd Font is a distinct family
    stow exit code 0 even when it linked somewhere wrong readlink -f, never $?
    azote Rewrites ~/.azotebg and starts a swaybg over sway's background pkill swaybg and reload
    config.d order Read alphabetically; theme sorts last and wins — so a $role used in default is not defined yet and sway fails with Invalid border color $accent Name overrides zz-local; source theme.env from a script when a binding needs a colour
    Undefined GTK colour An @name with no definition renders black, with no error and no fallback — it reads as a rendering bug, not a missing value Define every role in both palettes; theme refuses to switch when they disagree
    waybar include Precedence goes to the including file, so a module left in config silently beats the fragment Define a themed module only in the fragment
    foot reload No config-reload signal exists. SIGUSR1/SIGUSR2 only pick between the blocks loaded at startup theme … --restart-terminals, or log out
    foot [colors] Deprecated; warns on every launch Fragments use [colors-dark]
    Theme name case XCursor resolves by case-sensitive path. Qogir-dark never matched /usr/share/icons/Qogir-Dark, so the cursor silently stayed default ls -d /usr/share/icons/<name> before trusting a name
    bash -lc Line 6 of .bashrc is [[ $- != *i* ]] && return, so a non-interactive shell skips the whole file and the change looks unapplied Test with bash -ic
    Moving a config block Whatever stayed behind is lost, and every check here is syntactic — the waybar clock's scroll actions went this way unnoticed Diff old against new key by key; git show HEAD:<path>
    08

    Switching palettes

    Every colour in the setup is a named role, defined twice — once per palette — in a pair of fragments inside the package that owns it. A tracked symlink picks which fragment is live. Switching is flipping 17 of those symlinks.

    Press $mod+Shift+t. That is the whole day-to-day interface — it runs theme toggle. The bar, window borders, desktop, notifications, launcher, app grid and every GTK app change together; the three exceptions are listed below.

    Nothing needs a terminal, and nothing needs the repo. The rest of this phase is for when you want to see what it did, or when something looks wrong.

    shell
    ❯ theme                    # print the active palette
❯ theme gruvbox            # switch
❯ theme toggle             # the other one — what $mod+Shift+t runs

    Two flags. --no-icons skips papirus-folders, the only step needing sudo — use it in a script or over ssh, where there is no terminal to prompt on. --restart-terminals also restarts foot --server, applying the palette to the terminal immediately at the cost of every open shell.

    Each switch prints how many symlinks it flipped. It must say 17.

    shell
    ❯ sudo papirus-folders -C yellow -t Papirus-Dark   # gruvbox; -C nordic for nord
❯ theme --restart-terminals                        # or just log out

    Only needed if the switcher said it skipped them. It runs papirus-folders itself when a terminal is there to take the sudo prompt, and prints the exact line to run when there isn't — over ssh, from a keybinding, or under --no-icons.

    --restart-terminals closes every open terminal. foot has no config-reload signal at all, so there is no gentler option; skip it and new terminals are right while old ones stay as they were until you log out.

    Same sweep as phase 06, now under the other palette: $mod+d launcher · notify-send test · $mod+Shift+d drawer · the waybar clock tooltip, and scroll on it · $mod+f1 lock · thunar for GTK3 · any libadwaita app · $mod+Return terminal · Print · vim · ls.

    What each failure looks like: a black widget means a role the palette doesn't define — GTK CSS renders an undefined @name as black with no error. A surface still in the old palette means its fragment isn't named to the pattern and was never switched. A libadwaita app rendering light means ~/.config/gtk-4.0/gtk.css isn't linked.

    shell
    ❯ git -C ~/repos/dotfiles status --short   # 17 lines, all symlinks

    The symlinks are tracked, so the active palette is part of the repo's state. From a clean tree a switch produces exactly 17 modified paths and nothing else. Commit them or git checkout . — leaving them dirty makes every later diff noisy.

    shell
    ❯ theme                                    # what does it think is active?
❯ cd ~/repos/dotfiles && git status --short  # 17 lines, or 0 — never between
❯ theme nord --no-icons && theme gruvbox --no-icons

    A switch is all-or-nothing by construction: every fragment is checked to exist before any symlink moves, so a missing one aborts having changed nothing and names what's missing. If the tree shows some number other than 17 or 0 modified paths, something outside the switcher edited a symlink.

    Switching away and back re-flips all 17 from a known state. It is safe to run at any time and cannot half-apply.

    shell
    ❯ cd ~/repos/dotfiles/<pkg>/.config/<app>
❯ # write colors-nord.ext and colors-gruvbox.ext — same role names in both
❯ ln -sfn colors-nord.ext colors.ext       # relative and bare, never a path
❯ # point the app's config at colors.ext with its own include directive
❯ theme gruvbox --no-icons                 # must now say 18

    No code changes — the switcher finds its work by filename. The count going up by one is the confirmation; if it doesn't, the name doesn't match <base>-nord.<ext> / <base>-gruvbox.<ext> and the file will be silently left on one palette forever.

    If the package is unfolded — alacritty, gtk, vim, bin — the new files need stow -R <pkg> before they exist in ~ at all.

    Three things do not update immediately. foot — it has no config-reload signal, so open terminals and the running server keep the old colours until --restart-terminals or a logout. Running GTK apps — they read settings.ini once, at startup; restart the app. Folder icons — skipped when there is no tty for sudo; run the line the switcher printed. Everything else is live by the time the command returns.

    Never make the switcher a stow package. A theme-nord / theme-gruvbox pair writing into ~/.config/waybar would force stow to unfold that directory, and every themed package would lose the "new files appear for free" property checked in phase 04. Flipping a symlink inside the package leaves fold state untouched — which is why the fold table in the playbook is unchanged by any of this.

    Adding a themed application means adding two fragments and a symlink, and changing no code — the switcher discovers its work by filename. The sharp edge is the same fact from the other side: a file not named <base>-nord.<ext> / <base>-gruvbox.<ext> is silently never switched. There is no manifest to fall out of step with, and none to complain either.

    09

    The palettes

    Adding anything new means picking a role and supplying both values. The desktop drifted into four incompatible palettes because each config was themed on its own; it carries two coherent ones now only because every colour is named by role. Note that Nord and Nordic are different schemes — alacritty-theme ships both, and the GTK theme is genuinely called Nordic.

    RoleNordGruvboxUsed by

    Nord — the default

    Gruvbox Dark

    desktop is the one role not drawn from the palette on the Nord side. Nord has nothing below nord0, so it is a hand-darkened #272B33; gruvbox ships exactly this idea as bg0_h. The desktop being one shade below the window background is what turns the gaps into visible channels.

    The two are not interchangeable in temperature. Nord's accent is a cool frost blue with warning a long way off in yellow; gruvbox's accent is the yellow, with warning one hue step away in orange. Warning states read as hotter under Gruvbox rather than as a different colour. That is gruvbox, not a mistake in the mapping.
